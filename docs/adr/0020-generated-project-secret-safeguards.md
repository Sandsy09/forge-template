# 20. Ship neutral secret safeguards and keep scanning optional

## Status

Accepted

## Context

[ADR 0012](0012-conservative-foundation-scope.md) keeps Foundation
conservative and runtime-free, but already treats "base ignore rules protect
common secret-bearing local files such as `.env`" as an example of a neutral
safeguard Foundation may still own without becoming a runtime concern. [ADR
0016](0016-owner-local-environment-inputs.md) establishes the `.env` /
`.env.example` split — one gitignored local file, one tracked, safe,
placeholder-only example — but leaves the breadth of the ignore rule and any
enforcement of "placeholders only" to later work.

The current scaffold's safeguard is thin: `template/.gitignore` ignores
exactly `.env`, nothing else. Nothing catches a committed `*.pem`, a stray
`id_rsa`, or a `.env.example` that quietly gained a real value over time. At
the other extreme, generating a mandatory secret scanner would put a
third-party binary and its false-positive surface in every project's commit
path, failing the universal and provider-neutral conditions [ADR
0012](0012-conservative-foundation-scope.md) already set for Foundation
inclusion — no single scanner is right for every project, and forcing one
removes a real choice from projects that already have host-native scanning.

[ADR 0008](0008-remove-make-task-runner.md) already recorded the cost of
shipping an untested conditional: a `task_runner` choice that produced a
byte-empty `Makefile` because nothing in the validation suite ever exercised
it. That precedent argues directly against adding a `secret_scanning` Copier
question now, before any concrete integration exists to test.

## Decision

Adopt the [secret-handling safeguards](../secret-handling.md) as the
canonical living contract, and change the generated scaffold to match it:

- broaden `template/.gitignore` to cover the `.env` family and conventional
  credential/key artefacts, paired with an explicit `!.env.example` negation
  so the broader `.env.*` rule cannot silently untrack the tracked example;
- add `detect-private-key`, from the pre-commit-hooks repository the
  generated project already pins, to the generated pre-commit configuration;
- document secret handling in generated `SECURITY.md`; and
- add `render.check_secret_safeguards` and `render.check_env_example_tracked`
  so these properties are verified for every answer combination this
  repository scaffolds, rather than merely asserted in documentation.

Optional secret scanning is defined, not generated: any scanner a project
adopts should run at the pre-commit stage, scan full history, support a
reviewable baseline, and produce the same result locally and in CI. gitleaks
is named as the provider-neutral reference capability; GitHub push protection
and secret scanning are the parallel GitHub-platform contribution. Neither is
generated by this decision, and no `secret_scanning` Copier question is added.

This decision changes generated `.gitignore`, `.pre-commit-config.yaml`, and
`SECURITY.md` for new projects **and** for projects already scaffolded, once
they run `copier update`. It adds no Copier question, runtime dependency,
ProjectSpec field, or component manifest.

## Consequences

- New and updating projects gain a broader, tested secret-ignore surface and
  a local private-key guard, without any new third-party runtime dependency.
- `copier update` three-way merges the broadened `.gitignore`,
  `.pre-commit-config.yaml`, and `SECURITY.md` into projects scaffolded
  before this decision; the merge behaviour for each file is validated by
  this repository's `poe update` scenarios rather than assumed.
- The `!.env.example` negation becomes a permanent constraint on this ignore
  list: any future addition must be checked against the same shadowing
  hazard before merging.
- Optional secret scanning stays a documented choice until Stage 06's
  composition mechanics exist to generate it as a real capability or GitHub
  platform contribution; no untested conditional is added in the meantime.
- `render.check_secret_safeguards` and `render.check_env_example_tracked`
  make "placeholders only" and "the example stays tracked" mechanically
  enforced properties of every scaffold this repository produces, not just
  documented expectations.
